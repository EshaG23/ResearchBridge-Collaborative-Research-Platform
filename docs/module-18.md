# Module 18: history, document versions and contributions

The private community now links to Project history, Document versions and Contributions. History combines saved community/task events, uploaded files, project creation, accepted mentorship, recorded selection and agreement milestones. Filters support contributor, sprint, activity type and inclusive date ranges, with paginated results and authorised links to supporting work. Private agreement evidence and applicant resumes remain in their existing separately protected workflows.

Task uploads can explicitly replace a selected latest file. Exactly one replacement is permitted for a version operation. Every revision keeps its own stored file, number, uploader name, timestamp and revision note. Summary resources support the same explicit latest-version replacement. Legacy project documents continue to use their existing version workflow. The library groups version chains by a stable root document identifier and marks the latest version. Earlier submission evidence and file comments remain linked to their original file records. Pre-existing unlinked uploads are left as separate documents; filenames alone are not evidence of a version relationship.

Contributions derive from actual submissions, file/reference uploads, revisions, currently approved tasks and recorded reviews. A revised task counts once when approved. Reopening removes it from current approved totals. Contributor records use stable user IDs and remain visible even when membership or roles change. Saved display names accompany new events/files; migration snapshots existing names, since earlier historical names cannot be reconstructed. No ownership, authorship order, research-quality score or productivity ranking is assigned.

History begins from existing records. Legacy events without a saved sprint ID can only use the task's currently recorded sprint. Earlier unsaved or unrecorded actions cannot be reconstructed. Future project completion and IP events will be added with Module 19. All history/library/contribution routes recheck private-community access; file downloads use existing authenticated handlers.

Additional requested improvements: Module 17 now has a checklist layout with circular task actions, overdue dates, My tasks and Awaiting review filters, plus an expandable Completed list. A circle opens submission for the assignee; completion still requires review. The dashboard shows persistent per-user unread chat totals and project chat links, refreshing every 15 seconds. Own messages do not count. Opening a visible chat at the latest messages marks them read; counts survive logout and hidden/background chats do not silently clear them. On first rollout, existing incoming messages are unread until the chat is opened.

Validation: 149 regression tests passed. New tests cover task/summary version chains, immutable earlier reviews and comments, duplicate/replaced version rejection, contributor counts and name changes, private history access/filtering, per-user unread persistence and account guards. Isolated browser checks confirmed dashboard 1-to-0 unread behaviour, expandable Completed tasks and version 2 alongside version 1. The live database was backed up before migrations; no demo fixtures were added to it.
